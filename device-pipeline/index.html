Device Pipeline

Teach a new object from a few images

    Design guide · simple English

    Device Pipeline

    The user shows the system a new object with only 5–10 pictures. The system then looks through 2–3 days of saved camera video and finds many more pictures of that object. A person checks every result. The checked pictures then train the camera model so it can find the object by itself.

    Input
    5–10 example pictures and 2–3 days of saved video
    Output
    A checked training set and a better model
    Example
    A tray in a jewellery shop
    Works with
    Frigate NVR 0.18 (unchanged Docker image)
    Chapters
      00

      The idea in one minute

      To train a model, you need hundreds of labeled pictures. Users do not want to take hundreds of pictures. But the cameras already recorded the object many times. This pipeline finds those moments in the video for you.

      Step A

      Show

      The user marks the object in a few pictures.

      Step B

      Search

      The system searches the saved video for things that look the same.

      Step C

      Check

      The user says "yes" or "no" to each result.

      Step D

      Train

      The system trains the model with the checked pictures.

      This is the same idea as face recognition. The system makes a short number code, called an embedding, for each picture of the object. Pictures of the same object get codes that are close together. So the system can compare codes to find the object again.

      NOTE

      The search does not train anything. It only collects data. Training happens one time, at the end, after a person has checked the data.

      01

      The full pipeline

      The pipeline has ten steps. Steps 4 to 8 repeat two or three times. Each round finds more pictures than the last round.

      02

      Each step, simply

      02.1Seed: show the object

      The user opens a saved video, stops it where the object is, and draws a box around it. Do this 3–5 times, if possible at different times of day.

      CAUTION

      Phone photos are a weak start. A phone photo looks different from a camera frame: different angle, color, sharpness, and no night mode. Use them only if the object is not in the video yet. Boxes drawn on real video frames work much better.

      02.2Sample: pick useful frames

      Three days of video at 1 frame per second is about 260,000 frames for each camera. That is too many to search. So the system picks frames in a smart way:

      • When something moves, it takes more frames. Frigate already saves how much motion each 10-second piece of video has.
      • When nothing moves, it takes about one frame each minute.
      • It removes frames that are almost the same as the frame before.

      02.3Propose: cut frames into boxes

      A tray may fill only 2% of the picture. If you compare the whole frame with the tray, the shop, not the tray, decides the result. So the system first cuts each frame into many candidate boxes. It can use tiles of different sizes, or a model that finds "any object" in a picture. Then it compares each box, not the whole frame.

      02.4Search: compare with the seeds

      The system makes an embedding (number code) for each candidate box and for each seed. It then measures how close they are. A score near 1 means "very similar". The system puts the results into four groups:

      02.5Track: follow the object in time

      When the system finds the object in one frame, it follows the object forward and back in the video. The object moves, turns and changes light. So one good find gives many new views, for free. This is the strongest step in the pipeline, because the search alone finds only views that look like the seeds.

      02.6Check: the user decides

      The user checks the results in the app. To keep this fast:

      • The app shows one track at a time. One "yes" or "no" covers all frames of that track.
      • The app shows the "maybe" group first, because those answers teach the most.
      • A box-tightening tool fixes loose boxes. The user only moves a box when the tool is wrong.
      • Each round asks for a few hundred decisions at most.

      02.7Grow: search again

      The confirmed results become new seeds. The next search now knows how the object looks at night, from the side and when it is half covered. Two or three rounds are usually enough.

      02.8Label the rest

      Every picture can also show people, cars and other objects. These also need boxes. If they have no box, the model learns that a person is "background" and stops finding people. The current model draws these boxes automatically. The user only confirms them.

      02.9Positives and negatives

      TypeWhat it isWhy it helps
      PositiveA box that the user confirmed as the objectTeaches what the object looks like
      Look-alike (hard negative)A box that looks similar, but the user said "no"Stops false alarms. The most useful "no" example.
      Empty frameA frame where the object is not presentTeaches the normal scene
      Other objectsPeople, cars and other known things, with their own boxesKeeps the old classes working

      02.10Train

      • Fine-tune, do not start again. Start from the current model. Add some old training data, so old classes stay good.
      • Split by time. Put whole days or whole tracks in the test set. If frames from one track are in both sets, the test score looks better than the truth.
      • Test before release. The new object must reach the target score. The old classes must not get worse. Then run the new model in the background ("shadow mode") before it goes live.
      03

      Problems and fixes

      Each problem below can make a bad training set. The pipeline has one step to stop each one.

      ProblemWhat goes wrongFix in the pipeline
      Small object, big frameThe whole-frame code describes the room, not the objectCut frames into candidate boxes (step 3)
      Phone photos look differentThe first search misses most framesSeed with boxes on real video frames (step 1)
      Search finds only similar viewsNo night, side or half-covered pictures, so the model fails thereTrack (step 5), check the "maybe" group, grow in rounds (step 8)
      Video was deletedFrigate keeps only video with activity by default. A still tray makes no motion, so its video can be gone.Turn on continuous recording for the collection days
      Too much videoSearch takes days and costs a lotSmart frame sampling and copy removal (step 2)
      Too much to checkThe user gives upCheck by track, "maybe" first, a limit on each round (step 7)
      Loose boxesThe model learns wrong edgesBox-tightening tool, user adjusts (step 7)
      Other objects have no boxThe model forgets people and carsLabel the rest (step 9)
      Very similar objectsTwo trays get mixed upKeep look-alikes as "no" examples (02.9)
      Test score too goodSame track in training and testSplit by day or by track (02.10)
      New model is worseThe system misses people after an updateTest gate, shadow mode, automatic rollback
      PrivacyThe search sees every person in the videoRun the search at the site, and upload only checked boxes
      04

      Before you start

      1. Turn on continuous recording for the collection days: record.continuous.days: 3.
      2. Make sure that the disk can hold 3 days of video from each camera.
      3. Check that the site has a GPU for the search, or plan to run the search during the night.
      4. Tell the people in the shop that video is used to train the system, as the local law requires.
      5. Pick the object and the cameras that see it.
      6. After 2–3 days, start the pipeline from the app.
      record:
  enabled: true
  continuous:
    days: 3        # keep all video while you collect data
      WARNING

      Continuous recording uses much more disk space. Set it back to your normal value after the data is collected.

      Where it fits

      This pipeline is the "front end" of the Custom Model Pipeline. It replaces the "Collect" and "Auto-label" steps there. Everything after training (test gate, delivery, rollback) stays the same.
